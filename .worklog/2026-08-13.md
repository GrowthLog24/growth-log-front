## 주요 결정 사항

### 1. 버튼 3개 → 2개, 주 버튼은 블로그

| | 이전 | 지금 |
|---|---|---|
| 주 버튼 | 그로스로그 6기 알아보기 | **블로그 바로가기** |
| 보조 | 홈페이지 · 블로그 | 홈페이지 바로가기 |

블로그를 주 버튼으로 올린 이유 — 위키의 모든 항목이 결국 블로그 원문으로 이어지고,
위키를 다 읽은 사람이 **이어서 읽을 곳**이 거기다. 홈페이지는 이미 아는 곳이라 조용히 뒀다.

버튼만 빼면 바로 위 문구가 "6기 모집은 9월 1일까지입니다" 로 남아 말이 붕 뜬다. 함께 고쳤다.

> 격일로 모여 각자 막힌 곳을 쓰고, 그게 쌓여 이 위키가 됐습니다. 전체 성장일지는 블로그에 있습니다.

### 2. 푸터를 홈페이지와 동일하게 — 값을 옮겨 적었다

사이트 푸터는 `src/presentation/components/layout/Footer.tsx` 이고,
**주소·SNS 링크를 Firestore(`siteConfigRepository`)에서 받아온다.**
위키는 외부 의존이 없는 단일 HTML 이라 그걸 부를 수 없다.

그래서 **실제로 렌더된 값을 그대로 옮겨 적었다.** 확인한 값과 맞춘 결과:

| 항목 | 값 |
|---|---|
| 배경 · 위쪽 선 | `#f5f5f5` · `1px #eaeaea` |
| 안쪽 폭 · 여백 | `max-width 1280px` · `48px 32px` |
| 그리드 | 4열, 간격 32px, 첫 블록 2칸 차지 |
| 모바일(≤768px) | 1열로 쌓임 |
| 로고 · SNS | 로고 40px, 아이콘 3개(20px, 간격 16px) |
| 링크 | 13개 (로고 + SNS 3 + 바로가기 7 + 문의 2) |

이미지는 **절대 주소**(`https://www.growthlog.org/...`)로 부른다.
사이트에 올렸을 때와 파일을 따로 열었을 때 똑같이 보이게 하기 위해서다.

### ⚠️ 알려진 제약 — 푸터가 자동으로 따라오지 않는다

백오피스에서 주소·SNS 링크를 바꾸면 **홈페이지는 자동 반영되지만 위키는 안 바뀐다.**
위키 원본(`growthlog_wiki/index.html`)을 손으로 고치고 다시 빌드해야 한다.
해당 위치에 주석으로 표시해 두었다.

푸터 디자인을 손볼 일이 생기면 **위키도 같은 PR 에 함께 넣는 것**이 맞다.
(2026-08-13 혜린씨 확인 — 그렇게 하더라도 지금은 같은 모양으로 가기로 함)
