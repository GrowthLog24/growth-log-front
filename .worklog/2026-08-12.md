## 배경

위키는 이 레포 밖에서 만들어진 산출물이다.
`curation_dataset.csv`(성장일지 큐레이션 데이터) → `wiki-data.json` → 단일 HTML 로 빌드된다.
빌드 도구는 `growthlog_blog/tools/` 에 있고, 이 레포에는 **결과물 한 파일만** 들어온다.

- 기술 58개 · 성장일지 198편(위키가 덮는 고유 편수) · 회원 86명 · 1~5기
- 외부 라이브러리 없음. 데이터가 HTML 안에 인라인되어 요청 1회로 끝난다
- 그래서 `public/` 정적 파일로 두는 것이 맞다고 판단했다

## 주요 결정 사항

### 1. 서브도메인이 아니라 서브디렉터리 (`/wiki`)

`wiki.growthlog.org` 대신 `www.growthlog.org/wiki` 로 정했다.
검색엔진은 서브도메인을 별개 사이트로 취급하므로, 서브도메인으로 두면
`www.growthlog.org` 가 쌓은 도메인 신뢰를 위키가 물려받지 못한다.
위키는 롱테일 기술 키워드로 유입을 만드는 것이 목적이라 이 차이가 그대로 유입 차이가 된다.
같은 도메인이면 헤더·CTA·GA 세션도 그대로 이어진다.

### 2. `next.config.ts` 에 rewrite 추가 — 이게 없으면 조용히 실패한다

**확인한 사실** (dev 서버, 파일만 넣은 상태):

| 경로 | 응답 |
|---|---|
| `/wiki` | **404** |
| `/wiki/` | 308 → `/wiki` → **404** |
| `/wiki/index.html` | 200 |

`public/` 의 파일은 경로 그대로만 서빙되고 디렉터리 인덱스 해석이 없다.
파일만 넣으면 위키는 `/wiki/index.html` 에서만 열리고, canonical 이 가리키는 `/wiki` 는 404 다.
**페이지는 살아 있는데 검색엔진은 색인에서 빼는 상태**가 되므로 rewrite 를 넣었다.

```ts
async rewrites() {
  return [{ source: "/wiki", destination: "/wiki/index.html" }];
}
```

### 3. canonical 은 `https://www.growthlog.org/wiki` — www 포함, 끝 슬래시 없음

- **www 포함** — `SITE_METADATA.url` 이 `https://www.growthlog.org` 다. www 유무는 다른 주소다
- **끝 슬래시 없음** — `trailingSlash` 기본값 때문에 `/wiki/` 가 308 로 `/wiki` 로 간다.
  canonical 이 리다이렉트를 가리키면 안 된다

위키 원본(`growthlog_wiki/index.html`)의 canonical · og:url · JSON-LD 세 곳을 함께 맞췄다.

### 4. `sitemap.ts` 에 `/wiki` 등록

`robots.ts` 는 `/admin`·`/api` 만 차단하므로 위키는 크롤링 가능하다.
다만 sitemap 에 없으면 발견이 늦어져 등록했다. `changeFrequency: monthly`(기수 단위 갱신), `priority: 0.8`.

## 발생 이슈

### 이슈 1: `/wiki` 404 — 위 결정 2번

- 원인: Next.js `public/` 정적 파일에 디렉터리 인덱스 해석이 없음
- 해결: rewrite 추가. 세 경로(`/wiki`, `/wiki/`, `/wiki/index.html`) 모두 200 확인

### 이슈 2: 위키 원본의 회원 페이지 링크가 절반 이상 깨질 수 있었다

위키에서 회원 이름을 `/member/{기수}/{이름}` 으로 링크하려 했는데 두 가지 문제가 있었다.

1. **기수를 기술별로 뽑으면 틀린다.** 회원 인식 단위는 등록기수(= 전체 활동 기록 중 가장 앞 기수)인데,
   위키의 기술별 `members[].cohorts` 는 그 기술에서 활동한 기수만 담는다.
   실제로 54건이 어긋났다 (예: 강단 — React 블록 5기, 등록기수 2기)
2. **회원관리 명부에 없는 사람이 있다.** 86명 중 29명만 페이지가 존재했다
   (5기 15명 전원 · 4기 7/19 · 3기 2/28 · 2기 3/8 · 1기 2/16).
   회원관리는 아카이브가 아니라 **현재 명부**라서 정상이다

→ 위키 빌드에서 등록기수를 회원 단위로 계산하고, 실제 존재를 확인한 29명만 링크한다.
   나머지는 이름만 표시한다. 죽은 링크보다 링크 없는 편이 낫다.
   확인 도구: `growthlog_blog/tools/verify_member_pages.mjs` → `data/member_pages.csv`
