## 배경

기존 `/member/{기수}/{이름}` 라우트는 `member.redirectUrl`로 즉시 리다이렉트만 하는 껍데기 라우터였다.
이를 "경력 증빙용 개인 업적 페이지"로 전환하는 것이 이번 작업의 목표.

착수 전 확인한 제약:
- 출결 데이터가 코드베이스에 전혀 없었음 (컬렉션 · 엔티티 모두 부재)
- 성장일지는 `authorName` 문자열로만 회원과 연결되어 동명이인에 취약
- 프로젝트에는 참여자 정보 자체가 없고 `leaderName`만 존재

## 주요 결정 사항

### 1. 출결 문서 ID를 `{meetingId}_{memberId}` 조합키로 고정
Firestore에는 유니크 제약이 없어 `addDoc` 방식이면 저장을 반복할 때마다 중복 문서가 쌓이고
출석률이 100%를 넘는 버그가 된다. 조합키 + `setDoc`으로 중복을 구조적으로 차단.

### 2. 출결 문서에 `generation` · `round` 비정규화
Firestore는 조인이 없어 비정규화가 없으면 회원별 출결 조회가 N+1 쿼리가 된다.
회차 번호는 사실상 불변이므로 복제 비용이 정합성 위험보다 낮다고 판단.
단, 회차 수정 시 어긋나지 않도록 `meetingAdminRepository.update`에서 배치로 동기화.

### 3. 결석은 문서를 남기지 않음
관리자가 참석자만 체크하는 운영 방식을 지원하기 위해, 기록이 없는 회차는 도메인 집계에서
결석으로 간주. `saveMany`는 `absent` 입력을 문서 삭제로 처리해 불필요한 문서 증가를 막는다.

### 4. OG 썸네일을 Storage에 저장 (외부 URL 직접 참조 금지)
`next.config.ts`의 `remotePatterns`가 `firebasestorage.googleapis.com`만 허용한다.
여기서 `hostname: "**"`로 여는 것은 이미지 최적화 엔드포인트를 오픈 리레이로 만드는 행위라
채택하지 않았다. 대신 OG 이미지를 서버에서 받아 base64로 전달하고, 클라이언트가 기존
Storage 업로드 흐름에 태우도록 구현. 원본 블로그가 이미지를 내려도 업적 페이지는 유지된다.

### 5. `/api/og-preview`에 3중 SSRF 방어
`src/middleware.ts`의 인증은 `/admin` 경로에만 걸려 있어 API 라우트는 무인증 상태다.
"URL을 받아 서버가 대신 fetch"하는 엔드포인트를 그대로 열면 SSRF 프록시가 되므로:
1. `auth()` 세션 검사 (admin/editor만)
2. DNS 해석 후 사설 · 링크로컬 대역 차단 (169.254.x 클라우드 메타데이터 포함)
3. 리다이렉트를 수동 추적하며 매 홉 재검증 (공개 도메인 → 내부 주소 302 우회 차단)
추가로 HTML 512KB / 이미지 3MB 수신 상한과 8초 타임아웃 적용.

### 6. `redirectUrl` 데이터 보존
리다이렉트 동작은 제거했지만 값 자체는 유용한 개인 링크이므로 삭제하지 않고
업적 페이지 헤더의 "개인 페이지 방문" 버튼으로 노출.

### 7. React `cache()`를 page.tsx에 배치
`generateMetadata`와 페이지 본문이 같은 데이터를 필요로 해 Firestore 쿼리가 2배로 실행된다.
`cache()`로 요청 단위 메모이즈하되, application 레이어에 React 의존성이 들어가지 않도록
래핑 위치를 `page.tsx`로 선택 (CLAUDE.md의 "Application은 프레임워크 코드 금지" 준수).

### 주요 결정 사항 (2차)

**8. 출결 입력을 양방향으로 제공**
`/admin/meetings`는 "회차 → 전체 회원", 회원 상세는 "회원 → 전체 회차" 방향이다.
같은 attendances 컬렉션을 쓰지만 문서 ID가 조합키라 어느 쪽에서 저장해도
충돌 없이 같은 문서를 갱신한다. 이를 위해 `saveManyForMember`를 추가했다.

**9. 프로젝트 연결은 변경분만 갱신**
참여 정보가 프로젝트 문서(participantMemberIds)에 있으므로 회원 화면에서
저장할 때 전체 프로젝트를 쓰면 불필요한 쓰기가 발생한다.
초기 선택 상태와 비교해 바뀐 프로젝트만 업데이트한다.

**10. QR 다이얼로그 링크를 클릭 가능하게**
QR이 가리키는 업적 페이지를 관리자가 바로 확인할 수 있도록
URL 텍스트를 새 탭 링크로 전환했다.
