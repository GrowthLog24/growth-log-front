## 배경

이를 "경력 증빙용 개인 업적 페이지"로 전환하는 것이 이번 작업의 목표.

착수 전 확인한 제약:
- 출결 데이터가 코드베이스에 전혀 없었음 (컬렉션 · 엔티티 모두 부재)
- 성장일지는 `authorName` 문자열로만 회원과 연결되어 동명이인에 취약
- 프로젝트에는 참여자 정보 자체가 없고 `leaderName`만 존재

## 주요 결정 사항

### 1. 출결 문서 ID를 `{meetingId}_{memberId}` 조합키로 고정
Firestore에는 유니크 제약이 없어 `addDoc` 방식이면 저장을 반복할 때마다 중복 문서가 쌓이고
출석률이 100%를 넘는 버그가 된다. 조합키 + `setDoc`으로 중복을 구조적으로 차단.

### 2. 출결 문서에 `generation` · `round` 비정규화
Firestore는 조인이 없어 비정규화가 없으면 회원별 출결 조회가 N+1 쿼리가 된다.
회차 번호는 사실상 불변이므로 복제 비용이 정합성 위험보다 낮다고 판단.
단, 회차 수정 시 어긋나지 않도록 `meetingAdminRepository.update`에서 배치로 동기화.

### 3. 결석은 문서를 남기지 않음
관리자가 참석자만 체크하는 운영 방식을 지원하기 위해, 기록이 없는 회차는 도메인 집계에서
결석으로 간주. `saveMany`는 `absent` 입력을 문서 삭제로 처리해 불필요한 문서 증가를 막는다.

### 4. OG 썸네일을 Storage에 저장 (외부 URL 직접 참조 금지)
`next.config.ts`의 `remotePatterns`가 `firebasestorage.googleapis.com`만 허용한다.
여기서 `hostname: "**"`로 여는 것은 이미지 최적화 엔드포인트를 오픈 리레이로 만드는 행위라
채택하지 않았다. 대신 OG 이미지를 서버에서 받아 base64로 전달하고, 클라이언트가 기존
Storage 업로드 흐름에 태우도록 구현. 원본 블로그가 이미지를 내려도 업적 페이지는 유지된다.

### 5. `/api/og-preview`에 3중 SSRF 방어
`src/middleware.ts`의 인증은 `/admin` 경로에만 걸려 있어 API 라우트는 무인증 상태다.
"URL을 받아 서버가 대신 fetch"하는 엔드포인트를 그대로 열면 SSRF 프록시가 되므로:
1. `auth()` 세션 검사 (admin/editor만)
2. DNS 해석 후 사설 · 링크로컬 대역 차단 (169.254.x 클라우드 메타데이터 포함)
3. 리다이렉트를 수동 추적하며 매 홉 재검증 (공개 도메인 → 내부 주소 302 우회 차단)
추가로 HTML 512KB / 이미지 3MB 수신 상한과 8초 타임아웃 적용.

### 6. `redirectUrl` 데이터 보존
리다이렉트 동작은 제거했지만 값 자체는 유용한 개인 링크이므로 삭제하지 않고
업적 페이지 헤더의 "개인 페이지 방문" 버튼으로 노출.

### 7. React `cache()`를 page.tsx에 배치
`generateMetadata`와 페이지 본문이 같은 데이터를 필요로 해 Firestore 쿼리가 2배로 실행된다.
`cache()`로 요청 단위 메모이즈하되, application 레이어에 React 의존성이 들어가지 않도록
래핑 위치를 `page.tsx`로 선택 (CLAUDE.md의 "Application은 프레임워크 코드 금지" 준수).

## 이슈 수정 (3차) — 홈페이지와 개인 페이지의 노출 대상 분리

### 발견된 문제
사용자가 DB를 점검하다 발견. 홈페이지 활동 기록과 회원 개인 업적 페이지가
같은 `activities` 문서를 **구분 조건 없이** 공유하고 있었다.
실제 증상: 아직 개인 페이지 정보를 넣지 않은 회원의 페이지에 성장일지 3편이 표시됨.

직접적 원인은 2차 작업에서 넣은 **이름 폴백 조회**(`authorName` + `generation`).
마이그레이션 없이 기존 데이터를 살리려던 장치가, 홈페이지용으로 등록된 글을
동명 회원의 개인 페이지로 끌어왔다.

### Q7: 하나의 글이 양쪽에 동시 노출될 수 있어야 하는가
**답변**: 동시 노출 가능
**결정**: `showOnHome` 불리언 컬럼 1개를 `ActivityBase`에 추가.
"누구의 기록인가"(memberId)와 "어디에 보여줄 것인가"(showOnHome)를 독립 축으로 분리.

### Q8: 이름 폴백 처리
**답변**: 제거
**결정**: 공개 페이지에서만 제거하고 관리자 화면에는 유지.
양쪽 다 없애면 `memberId`가 빈 기존 글을 회원 상세에서 볼 수 없어
연결 작업 자체가 불가능해지기 때문.

### 주요 결정 사항 (3차)

**11. `showOnHome`은 "false일 때만 숨김"으로 판정**
`where("showOnHome", "==", true)`로 쿼리하면 Firestore가 존재하지 않는 필드를
동등 비교에서 제외하므로 **기존 문서 전부가 홈에서 사라진다**.
쿼리 조건이 아닌 결과 필터(`showOnHome !== false`)로 판정해 하위 호환을 지켰다.

**12. 미연결 글 연결 수단 제공**
폴백 제거로 `memberId`가 빈 글은 개인 페이지에 뜨지 않는다.
회원 상세 성장일지 탭에 "미연결" 뱃지와 "연결" 버튼을 두어,
수정 폼을 열지 않고 한 번에 `memberId`를 채울 수 있게 했다.

**13. 홈 노출 기본값을 등록 경로별로 다르게**
- 활동 기록 폼: 기본 켜짐 (기존 동작 유지)
- 회원 상세 성장일지 폼: 기본 꺼짐 (개인 기록이 목적)

### 노출 상태 매트릭스

| memberId | showOnHome | 노출 위치 |
|---|---|---|
| 있음 | true/없음 | 홈 + 개인 페이지 |
| 있음 | false | 개인 페이지만 |
| 없음 | true/없음 | 홈만 (큐레이션용) |
| 없음 | false | 어디에도 안 뜸 |

### 변경된 파일 (3차)
- `src/domain/entities/index.ts` — ActivityBase에 showOnHome 추가
- `src/infrastructure/repositories/activityRepository.ts` — 홈 조회에 showOnHome 필터, 개인 조회의 이름 폴백 제거
- `src/app/admin/activities/page.tsx` — 홈 노출 스위치
- `src/presentation/components/admin/member/MemberGrowthLogPanel.tsx` — 연결 버튼, 미연결 뱃지, 홈 노출 스위치

**15. 멤버 시트의 앞 3개 컬럼과 시트 이름을 그대로 유지**
예전에 받아둔 양식 파일도 계속 읽히도록 헤더를 바꾸지 않고 뒤에만 추가했다.
성장일지 시트가 없는 파일도 정상 처리된다.

**16. 이미지 URL의 빈 칸은 "지우기"가 아니라 "그대로 두기"**
`profileImageUrl` · `thumbnailUrl`은 엑셀에서 관리하기 번거로워, 빈 칸을 그대로
반영하면 실수로 이미지를 날리기 쉽다. 반면 `bio` · `field` 같은 텍스트는
엑셀에서 바로 지울 수 있으므로 빈 값을 그대로 반영한다.
이미지 제거는 회원 상세 관리에서만 가능하다.

**17. 정기모임 회차는 문서 ID가 아닌 회차 번호로 입력**
엑셀에 Firestore 문서 ID를 적게 할 수 없으므로 `기수 + 회차 번호`로
`meetings`를 조회해 `meetingId`를 채운다. 해당 회차가 없으면 존재하지 않는
회차 참조가 남지 않도록 `round`를 0(미지정)으로 저장한다.

**18. 연결할 멤버가 없는 성장일지는 등록하지 않고 경고**
멤버 시트에도 없고 기존 멤버에도 없는 이름·기수의 일지는 미리보기에서
별도 영역에 나열하고 제외한다. `memberId` 없이 등록하면 3차에서 폴백을
제거한 개인 페이지에 영영 뜨지 않는 유령 문서가 되기 때문.

**19. `create`에 신규 필드 추가 시 빈 문자열로 정규화**
Firestore는 `undefined` 값을 거부하므로 `profileImageUrl` 등 optional 필드는
`?? ""`로 정규화해 저장한다.
